# Development scripts

- [dev-database.mjs](dev-database.mjs): the root `npm run dev` pre-start check. When `DATABASE_URL` selects the existing project demo at `127.0.0.1:55432/ff_demo`, starts `.local/postgres-data` if stopped and checks readiness before Turbo launches either app. Reads the exported URL first, then the API's `.env.local`. Uses PostgreSQL tools matching the cluster version, from the standard Linux versioned directory or `PATH`. Never creates or resets a database, changes credentials, or manages custom databases. PostgreSQL stays running when the apps stop.
- [check-migrations.sh](check-migrations.sh): verifies that SQL migrations and journal entries match. Run from the repository root.
- [dev-runner.mjs](dev-runner.mjs): root `npm run runner` command. Ensures the local database is up, builds shared DB code, reads the owner-written `.local/runner/profiles.json`, registers the real connector, and prepares Project A1 before announcing readiness. `--help` runs without services; `--profile <id>` chooses the project default from the advertised profiles (required on first start, never guessed). `--enable-integration paseo` is the only way it contacts the local Paseo daemon; without it saved Paseo profiles and defaults are kept but not offered, and a saved default that is not offered prints "The saved project default profile is not advertised in this runner session. Select an available execution profile before Start." Work starts only through a task's Start action.
  Task 11: `npm run runner -- status`, `list` and `stop` reach only the saved local runner instance's private supervisor IPC and start nothing (no database, build, demo or Paseo). An instance that was never prepared prints "The local runner is not set up on this host. Run npm run runner first." On Ctrl+C the runner stops its own standalone workers and exits 0; if that cannot be confirmed it prints "Shutdown could not be confirmed. Check the runner's status before continuing." and exits 1.
- [dev-runner-setup.mjs](dev-runner-setup.mjs): guarded fixture-owner authentication, private durable enrollment, disposable Git repository, and authorized host/project setup. Uses a database session lock keyed by project to reject concurrent runners across checkouts. Restarts reuse credentials, host identity, repository edits and existing project instructions. Also serves the real connector, announces readiness after registration and project configuration, and closes it on SIGINT/SIGTERM.

Startup regressions live in [dev-database.test.js](../packages/fluent-flow/tests/unit/dev-database.test.js) and execute the real npm lifecycle with controlled external process fixtures.
Runner setup tests use the real mounted API, password service, separate PostgreSQL database and Git: [collab-local-runner.test.js](../packages/fluent-flow/tests/routes/collab-local-runner.test.js). Lifecycle tests run the real connector runtime and poll loop; only external Paseo SDK/CLI I/O is faked. They verify readiness, signal cleanup and lock release. The [CLI test](../packages/fluent-flow/tests/unit/dev-runner-cli.test.js) verifies help without requiring services.

Local runner errors identify a missing API or fixture credentials, no complete execution profile ("Configure a complete execution profile before starting the runner."), saved Paseo profiles without the flag ("Enable the saved integration explicitly or configure an available execution profile."), a profile id used twice across local and saved Paseo profiles ("Execution profile ids must be unique across local profiles and saved integrations. Fix the local configuration."), non-loopback configuration, production mode, a database outside the explicit local selection, unavailable profile, concurrent runner, missing/revoked enrollment, interrupted enrollment, unexpected demo directory, or conflicting project defaults. They stop setup without resetting credentials or replacing existing data. The default database must be the seeded loopback `ff_demo`, with matching private fixture output. For another disposable `ff_*` database, explicitly set `FF_LOCAL_RUNNER_DATABASE` to its exact name. Production mode is always rejected. Unexpected failures print "Local runner startup failed. Check that npm run dev is running and that a complete execution profile is configured." and log the detail to stderr. It never installs Paseo or creates an AI task automatically.

If enrollment commits but its one-time response or private state cannot be saved, `enrollment-pending.json` blocks a second enrollment. Restore the private state if available; otherwise revoke the unused `Local demo runner` through settings before explicitly removing that marker and retrying. A saved, verified enrollment clears a leftover marker automatically. Never remove `.local/runner` to resolve a running task: its journal retains execution and cleanup authority.
