# Deterministic Verification Machine — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace LLM-judged `test_verify` with deterministic red/green verification claims executed by runners, with server-owned red records, tamper checking, and full finding→requirement→test traceability.

**Architecture:** Server orchestrates (chain coordinator in `handleReviewResult`, transactional result persistence, server-inlined red records/config); runner executes in claim-scoped worktrees via framework adapters (LLM authors tests at the broken SHA; everything after is process spawns and byte comparisons).

**Tech Stack:** Node ESM, Express, raw pg + Drizzle, Zod, Vitest, Next.js 15 dashboard.

**Spec:** `docs/specs/2026-08-24-deterministic-verification-machine.md` (revised `b6d380a` after cross-provider review — read it before executing; this plan argues from it).

## Global Constraints

- ESM imports only; raw `pg` via existing `db`/`schema` from `@fluent-flow/db`; Zod for all validation; pino structured logs (`{ msg: '...' }`).
- Fail fast: every catch rethrows or annotates why it is safe to continue (CLAUDE.md).
- No secrets/internal detail in user-visible strings (check-run output, PR comments, dashboard) — CLAUDE.md Security section.
- Runner package stays dependency-free (no `@fluent-flow/db`, no `pg`) — duplicate Zod-free shape validation locally; server validates on receipt.
- `test_verify` stays in server config enums as deprecated-accepted; no code path creates it anymore.
- Vitest suites: server tests sequential (`--fileParallelism=false`), runner tests in `packages/fluent-flow-runner/tests/unit/`.
- Never execute commands authored by the LLM; commands come from adapters or repo config only.
- Commit messages follow repo convention; no co-author lines.

import { and, desc, eq } from 'drizzle-orm';
import { db, schema } from '../client.js';

const { verificationResults } = schema;

export async function insertVerificationResult(row) {
  const [inserted] = await db.insert(verificationResults)
    .values(row)
    .onConflictDoUpdate({ target: verificationResults.claimId, set: { ...row } })
    .returning();
  return inserted;
}

export async function getVerificationResultByClaim(orgId, claimId) {
  const [row] = await db.select().from(verificationResults)
    .where(and(eq(verificationResults.orgId, orgId), eq(verificationResults.claimId, claimId)));
  return row ?? null;
}

export async function getVerificationResultsForPR(orgId, repo, prNumber) {
  return db.select().from(verificationResults)
    .where(and(eq(verificationResults.orgId, orgId), eq(verificationResults.repo, repo),
               eq(verificationResults.prNumber, prNumber)))
    .orderBy(desc(verificationResults.createdAt));
}

async function runRed({ work, log, execute, client, sessionId }) {
  const hb = startHeartbeat(client, sessionId, work.claim_id);   // #118 pattern
  try {
    const cfg = work.payload.verification;
    const wt = await prepareWorktree({ ..., claimId: work.claim_id, ref: work.payload.red_base_sha }).catch(mapRefUnavailable);
    const detected = detectFramework(wt.worktreePath) ?? (cfg.framework === 'custom' ? CUSTOM : null);
    if (!detected) return complete('SKIPPED', { framework: 'custom', matrix: null });
    await runInstall(detected, execute, wt.worktreePath);
    const manifest = await authorTests({ work, detected, wt, ... });       // harness step, retries ≤ cfg.authoring.retries
    const redProof = await proveRed({ manifest, detected, wt, execute, reproductions: cfg.authoring.red_reproductions });
    const { artifactSha, hashes } = await commitAndPushRed({ manifest, wt, work });
    return complete('PASS', { phase:'red', framework: detected.id, manifest, test_hashes: hashes, artifact_sha: artifactSha, matrix: redProof.matrix });
  } finally { hb.stop(); }
}
