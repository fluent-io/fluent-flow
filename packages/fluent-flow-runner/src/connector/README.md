# Execution host connector

[Runner](../../README.md) · [Supervisor](../supervisor/README.md) · [Native transports](../native/README.md) · [Contract](../../../../docs/plans/2026-10-19-collaborative-contracts.md) · [Tests](../../tests/unit/connector/README.md)

The connector initiates authenticated HTTPS requests to Fluent Flow from the execution host. With the Paseo integration enabled it uses the pinned public `@getpaseo/client@0.12.0` API and the installed local Paseo CLI. The SDK is an optional peer: `runtime.js` imports it with `import()` only for a process started with `--enable-integration paseo` (or a caller that injects its own client), and maps only a missing `@getpaseo/client` package to `ConnectorConfigError('paseo_not_installed')`; a missing file or dependency inside an installed SDK keeps its real error and the generic startup failure. It opens no incoming listener. The existing review runner remains separate.

`runtime.js` composes the modules; `config.js`, `paseo-local.js` and `catalog.js` resolve private local configuration. `config.js` also validates standalone execution profiles (`loadLocalProfiles`, profile objects in `profiles`) against the pinned `NATIVE_PINS` enums with no defaults, keeps incomplete ones with problem codes, rejects an id that appears twice across local and saved Paseo profiles (`duplicate_profile_id`), reads per-backend `capacity` (default 1), and serves saved Paseo ids (`servedPaseoProfileIds`) only when Paseo is enabled. An id repeated within one source (two local entries, or one saved Paseo id twice) is rejected as `duplicate_profile_id` too, never collapsed. The connector publishes only allowlisted repository keys and profile settings.

**Standalone composition (Task 7).** `runtime.js` composes the standalone backends whenever the config has a `claude-code` or `codex` profile, with or without Paseo. `attachOrLaunchSupervisor` attaches to the supervisor that owns `<stateDir>` (`connectSupervisor`, role `connector`) and calls `launchSupervisor` only when none answers; a launch that loses the race (`OwnerLockHeld`) attaches to the winner. Tests inject their own supervisor client. Without Paseo there is no adapter, observer, Paseo wrap-up or stop command; the SDK is never imported.

- `catalog.js` publishes `formatVersion: 2` for a loaded config: every configured standalone profile (`id`, `name`, `backend`, `model`, `revision`, `capabilities` = `PUBLISHED_CAPABILITIES[backend]`, `readiness`, `harness` {name, pinned version}, public `policy`, `authExpectation`, `limits.maxActiveSessions`), plus saved Paseo profiles (backend `paseo`, harness `paseo@0.12.0`, `limits: null`) only when Paseo is enabled, and per-backend `capacity: { limit, available: null, observedAt: null }`. Initial availability is unknown; the connector's slot-aware polling below supplies current capacity observations. Readiness is the supervisor's current `status` for that profile; an incomplete profile is `incomplete`, and a profile the supervisor does not report (or no supervisor) is `platform_unsupported`. `profileRevision(profile, harnessVersion)` is `canonicalDigest({ backend, harnessVersion, model, policy, summaryProfileId }).slice(0, 16)`; for Paseo the private policy is the full launch selection (provider, mode, thinking and every feature value), so a matching revision proves the local profile is the frozen one without publishing features. Name, paths and capacity are outside it. Two daemon profiles under one served id are `duplicate_profile_id`. A directly injected legacy config (no `integrations`) keeps the v1 catalog. `PUBLISHED_CAPABILITIES` deep-equals `REQUIRED_CAPABILITIES` from `@fluent-flow/db` (test-only import; the runtime never imports the db package).
- `executor.js` routes by `payload.execution`. None: the v1 Paseo path unchanged (`integration_disabled` without an adapter), unless the session is journaled as an owned native session, whose cancel and permission go to its recorded backend's worker through the supervisor with no profile lookup. `schemaVersion: 2` + `paseo`: the same v1 adapter path and journal records, launched with the revision-verified local selection (the adapter never sees the envelope); a v2 follow-up prompt also needs the exact local revision before the adapter sends anything. `schemaVersion: 2` + `claude-code`/`codex`: the local profile revision must equal `execution.profileRevision` (`execution_settings_changed`, no supervisor call), then the supervisor (`profile_unavailable` when none is composed). Anything else is `profile_unavailable`. A supervisor `reconciling` outcome or a lost reply acks `ambiguous`. A native bind journals `{ backend, nativeSessionId, workspaceRef, generation, repositoryKey, role, model }` (never Paseo ids) and observes `workspace_bound { workspaceRef, backend }` and `session_bound { backend, nativeSessionId, generation }`. Native artifact reads and wrap-up follow the run's journaled native binding (see the Task 8 item below).
- Task 8: `runtime.js` exports `workspaceForBinding(binding, { paseo, supervisor })` (a native run's directory from the supervisor `workspace` method, a Paseo run's from its live worktree descriptor; null when unbound or archived), which artifact reads and Git sampling use. Run-level commands of a native run (`artifact_read`, `wrapup_preflight`, `wrapup`, which may name no session) follow the run's journaled native binding, never the Paseo adapter; a `summarize` without a native envelope on a native run is `summary_disabled` and starts nothing. An explicit native summary checks that its source session is a native session of the run on the summary's backend and that the frozen cursor is in that backend's domain, then submits that source reference (`summarySource`); the supervisor validates the history before any worker and appends the complete frozen history to the initial prompt from its own ledger, so the connector delivers only the server prompt. Any refusal is `summary_unavailable` (never truncated, never another model). Native archive requires the run branch to track the authorized push target frozen in the run's `create_worktree` record (see the [supervisor](../supervisor/README.md)); a missing or different target blocks with `upstream_unverified` or `upstream_mismatch`. `wrapup.js` `createNativeWrapup` maps `archive_sessions` to the supervisor closure and `archive_owned_workspace` to the supervisor archive, shapes results like the Paseo wrap-up (blocked note: "Worktree cleanup is blocked. Review the outstanding work.") and journals the existing `workspace_archived` receipt with `workspaceId` = the FF workspace reference; `journal.workspaceArchive` accepts a native binding's `workspaceRef`, so archived Git evidence stays readable after the directory is gone. `native-events.js` adds the supervisor `providerCursor` to every native observation, and `loop.js` keeps it when it recovers a journaled native observation.
- `worktrees.js`: `ensureRunWorktree` (FF-owned worktrees in `<stateDir>/worktrees/`, 0700; `workspaceRef` = `ffw_` + 16 hex; the `create_worktree` barrier is recorded before `git worktree add`; only a clean worktree of the repository on the expected branch at the recorded path is adopted; anything else is `worktree_conflict`, untouched, and `uncertain` when a barrier for the run already exists, so a recorded worktree that is now missing is never added again (Task 11 resolves it)) and `archiveRunWorktree` (never `--force`; uncommitted, untracked, upstream-less or unpushed work blocks it; the branch stays).
- `native-events.js`: `nativeObservation` maps spooled native events onto existing observation kinds (event id `<backend>:<sessionId>:<generation>:<nativeEventId>`, at most 180 characters; a turn completion is an `idle` session and never changes task status (an earlier `running` keeps its inherited move to `in_progress`; nothing native moves a task further); a native interruption projects no state, and the supervisor's `ff:cancel:<commandId>` confirms a Cancel as `cancelled`; usage keeps unknown counts null and reported attribution; plans become workpad plans; requests become attention; a profile violation is `reconciling` until the owned stop proves quiescence, and a native terminal spooled with `ownedStop` pending/uncertain stays `reconciling` too). `createNativeEventPump` journals each event (through the runtime's `remember`, which applies observation privacy) before acknowledging it to the supervisor; a failure before that leaves the acknowledgement unchanged, and the journal records each id once. A native summary session's assistant output becomes a `summary` observation when its turn completes.
- Task 10: with standalone backends, `runtime.js` gives `loop.js` a `capacity` provider over the supervisor's `reserveSlots`/`releaseSlots`. Each poll reports `availableSlots`; grants the server did not use (commands without `slotGranted`) are returned at once. While a poll is held the loop re-checks every second; a freed slot aborts the poll and re-polls with it, never sooner than one second after the aborted poll started. Every poll states `notAfter`, its deadline on the server's clock (last known `serverTime` from registration or an answer, plus elapsed time, the hold and a 5 s margin); the server claims no slot work for it later than that. A lost or aborted poll's batch, and batches left by an earlier connector connection, are never returned on time or disconnect: the loop returns a held batch only from an answered poll whose `serverTime` is past that batch's deadline (so its poll can never claim again), and only what `heldClaims` (the server's exact count of this host's outstanding claims) and that answer's `slotHeld` redeliveries do not need. A command the supervisor `deferred` for capacity is left unacknowledged (the server redelivers the same id). `executor.js` passes `slotGranted`/`slotHeld` to the supervisor and sends a Cancel for a native session with no binding (its launch deferred, its poll answer lost, or a restarted connector) to the supervisor by the server-provided `nativeBackend`, never to the Paseo adapter, reporting `cancelled` with `dispatched: false` only on the supervisor's own evidence. The 25 s hold, 1 s idle floor, 200 ms observation flush and 15 s heartbeat are unchanged.
- `loop.js` sends a native observation larger than one batch as ordered base64 fragments of its exact UTF-8 JSON (`<eventId>#f<index>/<count>`); it leaves the pending set only when every fragment was accepted, and later observations of that session are not sent until then (sending is not acceptance; other sessions keep flowing). Legacy observations keep the unavailable-record rule. Provider configuration and local daemon credentials stay on the host. `connector-client.js` implements the fenced server protocol; `url-guard.js` requires HTTPS except loopback test endpoints.

`journal.js` (on the shared fsynced primitive `durable-log.js`, also used by the [supervisor ledger](../supervisor/README.md); the ledger also passes `openFile` for descriptor-only no-follow access and `validate` to check records before torn-tail repair, while the journal passes neither and keeps its original rules) records intents, stable workspace/session bindings, prompt attempts, observations, confirmations and provider cursors in a private fsynced journal. `paseo-adapter.js` translates the public native lifecycle; `executor.js` checks local allowlists and current permission requests. `loop.js` requires an explicit accepted-state grant and ready observation before the initial prompt. Lost grants and transient observer failures hold the same command for recovery. Observation requests are capped at 100 events and 1 MiB of actual UTF8 JSON; an oversized legacy event becomes an explicit unavailable record, and an oversized native event is fragmented (above), never replaced.

Poll cadence: the loop asks the server to hold empty polls (`pollWaitMs`, default 25 s). If an empty answer comes back sooner, it waits out the rest of a 1 s idle cycle (`minIdlePollCycleMs`) so it cannot spin; held polls and non-empty batches go straight to the next poll. Live observations from `enqueueObservations` flush on a 200 ms coalescing timer (`observationFlushDelayMs`), independent of the poll and the 15 s heartbeat; flushes never overlap and a backlog keeps draining. `stop()` interrupts every wait.

New native workspace IDs are `wks_` followed by the first 16 hexadecimal SHA256 characters of `ff:workspace:<runId>`, matching the pinned protocol schema. Agent IDs remain deterministic UUIDv5 values. Existing journal bindings are reused verbatim; the connector never renames or recreates recorded resources to adopt a new ID algorithm. Native timeline requests receive safe numeric sequence cursors; durable/server cursor values retain their string representation.

`observer.js` waits for subscription readiness, backfills history, reconciles pending permissions and persists cursors. Native plans remain in the transcript and project into the workpad. Native turn state, progress and available usage are reported with their source session. Native cancellation confirms a cancellation request; an idle snapshot never proves that a turn completed. Summary sessions preserve their selected source cursor and configured model, and publish observed assistant output only after native completion.

`observation-privacy.js` copies observation payloads before journal persistence and transport. Known owned workspace directories become `[workspace]`, configured source roots become `[source]`, and Paseo home becomes `[paseo-home]`, preserving relative suffixes. Exact known host, daemon and session reporting credentials become `[redacted]` in text. Native SDK requests retain their original paths, metadata and credentials. Permission replies map an offered display choice back to its current native option; arbitrary free text is never expanded into a local path or secret, and ambiguous choices are rejected.

`redaction-context.js` retains newly delivered reporting credentials separately from the intent journal in `redaction-context.json`, under the connector state directory. It writes by atomic rename with file/directory fsync and enforces directory mode 0700 and file mode 0600. Host tokens and daemon passwords are loaded from their original local files each startup. Optional config `redactionSecretsFile` names an absolute local path to a private, user-owned, non-symlink regular file containing a JSON array of non-empty strings, for example `["prior-session-reporting-credential"]`. It is loaded before observer startup; seed values are not copied into the generated context. Keep the seed configured while older sessions may report those credentials. Missing, malformed or non-private seed/context files stop startup with a generic local error. This covers known configured values, not unknown secrets, encoded data or general DLP. Previously acknowledged history is preserved; this feature does not rewrite old observations.

Native `snapshot.lastUsage` is sampled at startup, reconciliation/reconnect and terminal events, including sessions already idle. One stable `native-session-snapshot` sample per session replaces its previous cumulative values; unchanged snapshots have a stable observation ID and do not duplicate across restart. Input tokens use the native `inputTokens` field, excluding the separately reported `cachedInputTokens`; no combined total or price is inferred. Cached input and context-window counters remain in the raw usage observation when the database has no corresponding metric column. Missing values are null and reported zero remains zero. Raw reported cost is preserved exactly in the observation; the existing SQL cost projection stores six decimal places. Project insights use a known cumulative session snapshot instead of adding overlapping turn samples; unavailable snapshots retain known turn metrics as fallback.

`artifacts.js` reads bounded files inside the exact journaled run workspace, refuses traversal, symlink escapes and credential files, verifies the opened descriptor remains inside that workspace before reading bytes, and restricts media types. `workpad.js` reads real Git HEAD and dirty/upstream state. `wrapup.js` rechecks Git, session state and journal ownership immediately before archive; missing ownership, foreign sessions, unknown state, dirty/untracked files, missing upstream and unpushed commits block cleanup. `inventory.js` inventories existing Flowly data without claiming to migrate it. `paseo-cli.js` resolves the installed CLI and sends a single scoped stop request; `uuid-v5.js` supplies stable workspace and agent IDs.

Confirmed owned workspace archive persists a durable local receipt with its fresh safe preflight. Subsequent Git sampling publishes that exact commit and clean state as historical evidence (`workspaceState: "archived"`, `historical: true`, `source: "owned_workspace_archive"`), then stops reading the removed directory. Stable observation IDs survive restart. Previously successful wrapup observations with matching journal ownership and clean pushed Git evidence also serve as receipts, allowing their historical HEAD to restore an already-unknown projection. Sampling waits for an in-flight archive and rechecks after a Git read. Failed, partial, session-only, foreign or unconfirmed missing workspaces grant no archive authority; unexpected missing Git state remains unknown.

Runtime limitations: the connector requires Node 22 or newer with native WebSocket support; the legacy runner still supports Node 20. It cannot reconstruct native terminal events that the daemon no longer retains. Missing history is shown as a warning, with a fresh cursor window after reset. Summaries require explicit project configuration and a separate authorized command. No provider cost is inferred when unavailable.
