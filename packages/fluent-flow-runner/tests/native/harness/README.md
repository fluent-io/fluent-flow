# Native probe harness

[Native probes](../README.md) · [Evidence](../evidence/README.md)

Test-only code. Nothing here is imported by `src/`.

| File | Purpose |
| --- | --- |
| `netns-launcher.js` | Re-runs itself with `unshare --user --map-user=<uid> --map-group=<gid> --keep-caps --net --mount`, the caller-UID mapping the brief's namespace amendment prefers over the original `--map-root-user --net`. Inside the namespace it makes every mount private (`mount --make-rprivate /`) and runs `ip link set lo up`. It then mounts a namespace-local sysfs so `/sys/class/net` describes this namespace. That sysfs would hide the host's existing `/sys/fs/cgroup` mount, so when one exists the launcher first binds it to a private 0700 temp directory (`mount --rbind`), binds it back on top of the new sysfs and detaches the temporary binding (`umount -l`). No cgroup mount is ever created, and without an existing one these steps are skipped. A final check fails setup unless no mount propagates and the original cgroup mount (same device and type) still serves `/sys/fs/cgroup`. The temp directory is removed after setup succeeds or fails; a failed removal runs nothing. The log line reports `cgroup=preserved|absent`. Every setup command used exits 0 on success; `mount --move` was not used because in a user namespace util-linux exits 32 after the move has already happened. The launcher then awaits `assertNetworkIsolation()`, writes `ready` on fd 3, drops namespace capabilities with `setpriv` and runs the command with `FF_NATIVE_REQUIRED=1`. If an attempt ends without `ready` (an `unshare` failure or an inner setup failure), it falls back once to `--map-root-user`. Once `ready` arrives the command's exit code, 86 included, is final and nothing is rerun. The mapping used is logged as `mapping=caller|root` with the actual `uid_map`. A missing `unshare`, `ip`, `mount` or `setpriv`, or setup failure under both mappings, prints `network_isolation_unavailable` and exits 1. It never uses sudo, sysctl, AppArmor or host network or mount changes: the `--mount` namespace is private and the sysfs remount stays inside it (an accepted deviation from the brief's launcher text; see the evidence README). `runOuter`, `runInner` (with an always-run `cleanup`), `planSetup`, `cgroupPreserved`, `propagationPrivate` and `hasCgroupMount` are exported for unit tests; importing the module runs nothing. |
| `db-bridge.js` | Task 7: `startDbBridgeOutside({ databaseUrl, dir })` creates a private 0700 temp directory with a 0600 Unix socket `db.sock` that pipes every connection to the URL's own `127.0.0.1:<port>` and nowhere else; `startDbBridgeInside({ databaseUrl, socketPath, port? })` listens on `127.0.0.1:<the same port>` (the default-suite test passes a free port) and pipes each connection through `db.sock`. A host other than `127.0.0.1` or a URL without an explicit port is `database_bridge_refused`. No other port, host or socket is bridged and no destination can be chosen. Both halves close with the suite and the directory is removed. |
| `test-containment.js` | Task 7: `testContainment({ spawnEnvExtras })`, containment operations for native tests whose subject is not containment. Each worker is its own process group standing in for a leaf: `read` is populated while a member lives (Task 10: and lists the group's live members with their identities, like `readContainment`), `kill` signals exactly that group, and `holds` (Task 8) says whether a recorded live process is still in that group. `spawnEnvExtras` adds the XDG roots and deny-proxy variables to native children, as the backend suites do. It never touches a cgroup. Task 11 adds `terminate` (`terminateVerified`) and `realTestContainment({ stateDir, instanceId, spawnEnvExtras })`, the real verified scope of that instance with the same env additions at spawn; the test entry uses it when `fixtures.containment` is `'real'` and removes its scope on exit when every leaf is empty. |
| `start-test-supervisor.js` | Task 7: `startTestSupervisor({ stateDir, instanceId, configFile, fixtures })` runs the real `startSupervisor` in its own process under `flock(1)` exactly as `launchSupervisor` does (owner lock on fd 4, readiness on fd 3), so the owner-lock proof stays real. `test-supervisor-entry.js` composes `syntheticClaudeAuth`, `syntheticCodexAuth` and `testContainment` as constructor arguments, with `fixtures.parentEnv` (temp `HOME`) as the natives' parent environment. The production entry never reads its configuration variable. `close()` signals the supervisor group; tests stop their workers first through the `stop` IPC method. Task 11: the return value adds `exited`, and the entry also ends after a `stop` that returned `stopped`. Task 8: `pidNamespace: true` runs the same command under `unshare --user --map-current-user --pid --fork --mount --mount-proc`, so the supervisor's /proc shows only its own process tree (inside the launcher every host process is outside this suite's user namespace and its /proc links are unreadable). |
| `test-supervisor-entry.js` faults | Task 11 concern pass, test entry only: `fixtures.dropThreadStart: n` drops the reply to the first `thread/start` of the next n worker spawns (the request is still written); `fixtures.killNoop: true` replaces the containment kill with a no-op, so a stuck leaf cannot be proven empty. Production never reads them. `startTestSupervisor().close()` now waits until the supervisor process under `flock` has exited, not only `flock`. |
| `ipc-connector-child.js` | Task 11: a connector in its own process for crash tests. It connects with the `connector` role, submits and delivers the command given in `FF_TEST_CONNECTOR`, optionally acknowledges the first spooled event, prints each step and then waits to be killed. |
| `isolation.js` | `assertNetworkIsolation({ sysClassNet, connect })` resolves only if the directory lists only `lo` and a TCP connect to `192.0.2.1:9` fails with `ENETUNREACH` within 1 s. |
| `binaries.js` | `requireNativeBinary(backend)` applies the skip rule and the exact version check. `platformCodex(executable)` (moved from the capacity test in Task 11) returns the pinned platform binary behind the npm Codex launcher, checked against the pin. |
| `context.js` | `createProbeContext(backend)` creates a mkdtemp root with `home/` and `context/` (0700) and a Git repo planted with `CLAUDE.md`/`AGENTS.md` markers, a project hook that writes a marker file, a `.mcp.json` server and `.codex/config.toml` (`model = "planted-model"` plus an MCP server). A committed repo-root `config.toml` defines a third planted server. All planted MCP URLs point at a loopback recorder, so any attempt to start them lands in `plantedHits`. The context also has `worktreeDir`, the realpath of a linked worktree (`ff-probe-worktree`) of the planted repo. `cleanup()` is async. `probeSpawnExtras` adds the XDG roots and proxy variables. |
| `sse-turns.js` | Shared script bookkeeping: claims turns, holds and releases them, records `unexpected`. A `{ text }` turn may give `text` as a function of the request body (Task 9), so an echo shows only what the native actually passed to the model. |
| `anthropic-fixture.js` | `startAnthropicFixture({ script, mainModel?, modelScripts? })` serves Messages API SSE turns. Main requests carry tools; known side requests (`count_tokens`, tool-less messages) get a default reply. Task 8: `modelScripts` adds further main models, each with its own ordered script (`requestsFor(model)`, Task 11: `releaseFor(model, turn)`), and replies carry the requested model. Request bodies are decoded whole, so a multibyte character split across chunks is never corrupted. |
| `openai-fixture.js` | `startOpenAiFixture({ script, mainModel?, modelScripts? })` serves Responses API SSE turns (Task 8: per-model scripts with `requestsFor(model)`, whole-body decoding; Task 10: an `{ httpError: { status, body } }` turn answers with that synthetic error). Codex MCP namespace tools are addressed as `<namespace>.<tool>`. |
| `mcp-fixture.js` | `startMcpFixture({ token })` is a Streamable HTTP (JSON) MCP server with one tool, `ff_probe_report`. It records each call and its `Authorization` header. |
| `deny-proxy.js` | `startDenyProxy()` refuses CONNECT and plain requests and records `host:port`. |
| `synthetic-auth.js` | `syntheticClaudeAuth({ fixture })`, the test-only Claude auth policy: it admits only the dummy `ANTHROPIC_API_KEY` source and its `env()` points the native at the loopback fixture. Tests pass it to `createClaudeBackend`; production never imports it. `syntheticCodexAuth({ fixture })` is the Codex counterpart: it admits only `account/read` `{ account: null, requiresOpenaiAuth: false }` (X3), never an auth mode, and its `args()` route the native to the loopback Responses fixture with the dummy key `FF_PROBE_OPENAI_KEY` from `env()`. |
| `evidence.js` | Writes sanitized per-probe JSON under `../evidence/<backend>-<version>/`. Temp roots and the real home become placeholders. |
