# Paseo connector

[Runner](../../README.md) · [Contract](../../../../docs/plans/2026-10-19-collaborative-contracts.md) · [Tests](../../tests/unit/connector/README.md)

The connector initiates authenticated HTTPS requests to Fluent Flow from the execution host. It uses the pinned public `@getpaseo/client@0.12.0` API and the installed local Paseo CLI. It opens no incoming listener. The existing review runner remains separate.

`runtime.js` composes the modules; `config.js`, `paseo-local.js` and `catalog.js` resolve private local configuration and publish only allowlisted repository keys and profile settings. Provider configuration and local daemon credentials stay on the host. `connector-client.js` implements the fenced server protocol; `url-guard.js` requires HTTPS except loopback test endpoints.

`journal.js` records intents, stable workspace/session bindings, prompt attempts, observations, confirmations and provider cursors in a private fsynced journal. `paseo-adapter.js` translates the public native lifecycle; `executor.js` checks local allowlists and current permission requests. `loop.js` requires an explicit accepted-state grant and ready observation before the initial prompt. Lost grants and transient observer failures hold the same command for recovery. Observation requests are capped at 100 events and 1 MiB of actual UTF8 JSON; an oversized event becomes an explicit unavailable record.

New native workspace IDs are `wks_` followed by the first 16 hexadecimal SHA256 characters of `ff:workspace:<runId>`, matching the pinned protocol schema. Agent IDs remain deterministic UUIDv5 values. Existing journal bindings are reused verbatim; the connector never renames or recreates recorded resources to adopt a new ID algorithm. Native timeline requests receive safe numeric sequence cursors; durable/server cursor values retain their string representation.

`observer.js` waits for subscription readiness, backfills history, reconciles pending permissions and persists cursors. Native plans remain in the transcript and project into the workpad. Native turn state, progress and available usage are reported with their source session. Native cancellation confirms a cancellation request; an idle snapshot never proves that a turn completed. Summary sessions preserve their selected source cursor and configured model, and publish observed assistant output only after native completion.

`observation-privacy.js` copies observation payloads before journal persistence and transport. Known owned workspace directories become `[workspace]`, configured source roots become `[source]`, and Paseo home becomes `[paseo-home]`, preserving relative suffixes. Exact known host, daemon and session reporting credentials become `[redacted]` in text. Native SDK requests retain their original paths, metadata and credentials. Permission replies map an offered display choice back to its current native option; arbitrary free text is never expanded into a local path or secret, and ambiguous choices are rejected.

`redaction-context.js` retains newly delivered reporting credentials separately from the intent journal in `redaction-context.json`, under the connector state directory. It writes by atomic rename with file/directory fsync and enforces directory mode 0700 and file mode 0600. Host tokens and daemon passwords are loaded from their original local files each startup. Optional config `redactionSecretsFile` names an absolute local path to a private, user-owned, non-symlink regular file containing a JSON array of non-empty strings, for example `["prior-session-reporting-credential"]`. It is loaded before observer startup; seed values are not copied into the generated context. Keep the seed configured while older sessions may report those credentials. Missing, malformed or non-private seed/context files stop startup with a generic local error. This covers known configured values, not unknown secrets, encoded data or general DLP. Previously acknowledged history is preserved; this feature does not rewrite old observations.

Native `snapshot.lastUsage` is sampled at startup, reconciliation/reconnect and terminal events, including sessions already idle. One stable `native-session-snapshot` sample per session replaces its previous cumulative values; unchanged snapshots have a stable observation ID and do not duplicate across restart. Input tokens use the native `inputTokens` field, excluding the separately reported `cachedInputTokens`; no combined total or price is inferred. Cached input and context-window counters remain in the raw usage observation when the database has no corresponding metric column. Missing values are null and reported zero remains zero. Raw reported cost is preserved exactly in the observation; the existing SQL cost projection stores six decimal places. Project insights use a known cumulative session snapshot instead of adding overlapping turn samples; unavailable snapshots retain known turn metrics as fallback.

`artifacts.js` reads bounded files inside the exact journaled run workspace, refuses traversal, symlink escapes and credential files, and restricts media types. `workpad.js` reads real Git HEAD and dirty/upstream state. `wrapup.js` rechecks Git, session state and journal ownership immediately before archive; missing ownership, foreign sessions, unknown state, dirty/untracked files, missing upstream and unpushed commits block cleanup. `inventory.js` inventories existing Flowly data without claiming to migrate it. `paseo-cli.js` resolves the installed CLI and sends a single scoped stop request; `uuid-v5.js` supplies stable workspace and agent IDs.

Confirmed owned workspace archive persists a durable local receipt with its fresh safe preflight. Subsequent Git sampling publishes that exact commit and clean state as historical evidence (`workspaceState: "archived"`, `historical: true`, `source: "owned_workspace_archive"`), then stops reading the removed directory. Stable observation IDs survive restart. Previously successful wrapup observations with matching journal ownership and clean pushed Git evidence also serve as receipts, allowing their historical HEAD to restore an already-unknown projection. Sampling waits for an in-flight archive and rechecks after a Git read. Failed, partial, session-only, foreign or unconfirmed missing workspaces grant no archive authority; unexpected missing Git state remains unknown.

Runtime limitations: the connector requires Node 22 or newer with native WebSocket support; the legacy runner still supports Node 20. It cannot reconstruct native terminal events that the daemon no longer retains. Missing history is shown as a warning, with a fresh cursor window after reset. Summaries require explicit project configuration and a separate authorized command. No provider cost is inferred when unavailable.
