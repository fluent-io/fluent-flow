# Native transport unit tests

[Runner](../../../README.md) · [Modules](../../../src/native/README.md) · [Native probes](../../native/README.md) · [Fixtures](fixtures/README.md)

These run in the default `npm test` and never spawn a native binary. They use in-memory streams and fake channels.

| File | Covers |
| --- | --- |
| `jsonl.test.js` | 1-byte chunking with multibyte UTF-8, `line_too_long`, `torn_final_line`, `invalid_json`, drain-aware `send`, `stream_closed`, and `fail` (first error kept, both streams destroyed, sends rejected). |
| `claude-control.test.js` | `request_id` correlation, `control_error`, answering each CLI request once, handler throw becomes an error response, `control_cancel_request`, the `client_composed` user envelope, ignoring the echo of our own answer (seen on 2.1.317), `unknown_response` rejecting requests and closing a real JSONL channel, `control_timeout`. |
| `codex-rpc.test.js` | No `jsonrpc` member, id correlation, server requests answered under the same id, ordered notifications, `unknown_response` rejecting requests and closing a real JSONL channel, `control_timeout`. |
| `native-env.test.js` | Ambient credential, gateway, proxy and `NODE_OPTIONS` removal, exact per-backend key sets, inherited `HOME`, no mutation of `parentEnv`/`process.env`, `contextDir` validation; `pins.js` versions, Claude argv (one `--add-dir <workspaceDir>`, `--setting-sources user`, strict MCP), `codexLaunchControls`, codex argv and version parsing; `FF_QUESTIONS_TOKEN` only when given, the four `codexQuestionServerOverrides` keys, the hold below the 7-day tool timeout, and `NATIVE_PINS` enums unchanged. |
| `claude-normalize.test.js` | `normalizeClaudeEvent` over the captured 2.1.317 transcripts in [`fixtures/`](fixtures/README.md): ordered timeline items with stable ids, per-model usage with `null` for unknown values and estimated cost, and failed terminals from `is_error` or a non-success subtype (`profile_unavailable` after a missing model, also with an interrupt outstanding); only `aborted_streaming`/`aborted_tools` are `interrupted`. |
| `claude-readiness.test.js` | The production policy (`claudeSubscriptionAuth()`) with injected platform, version and auth-status readers: unpinned version, API-key or signed-out auth, non-Linux, refused and unproven permission modes (protected reasons in the log only), and `admitClaudeInit` for the init mode, model, reporter and auth source; the `claudeSubscriptionAuth` shapes taken from the pinned 2.1.317 code; and a subscription-like init account refused when the fresh auth status is not `claude.ai`. |
| `claude-backend.test.js` | The backend against [`fixtures/fake-claude-child.js`](fixtures/README.md) (no native binary) and Task 4's real ledger and `createCommandBarrier`, with barrier promises held open: a send still awaiting its barrier when the interrupt is written is never written and settles `cancelled`/`dispatched: false`; a send written while the interrupt awaits its barrier is settled only by native evidence; missing evidence plus a closed stream is `reconciling`; a proven idle worker settles nothing; a request withdrawn, or a stream closed, while the response barrier is awaited settles `request_unavailable` with no write; a privateDir at or under the worktree (`..private` included) is refused before any write or spawn, and an outside sibling is accepted. |
| `codex-normalize.test.js` | The captured 0.162.1 transcripts: ordered timeline items, usage for the actual model, the missing-model terminal (`profile_unavailable`, no provider text), `serverRequest/resolved` with no decision, unknown usage as `null`, and approval choices (command `availableDecisions` exactly and in order, file change, permissions, MCP tool call, unsupported methods). The concern pass adds the X15 classification (only the 400 `model_not_found` body is `profile_unavailable`; no 404 variant is) and MCP remember scopes. |
| `codex-readiness.test.js` | The production policy (`chatgptSubscriptionAuth()`) with injected platform, version and account readers: unpinned version, apiKey/Bedrock/no account, empty overlays and auth modes, `admitCodexThread` mismatches, and refused or unrecorded approval policies as `invalid_config` with reasons only in logs. |
| `codex-backend.test.js` | The model-return validity gate treats an own-thread report from another model back to the selected one (scoped and missing-turn), or with a missing or invalid source, as a profile violation with one owned stop, fenced sends (pending barrier included), a failed terminal and retained usage; a genuine selected-to-selected report changes nothing. Retained-process classification admits only the exact `codex-code-mode-host` sibling executable parented by the recorded Codex worker. The backend against [`fixtures/fake-codex-child.js`](fixtures/README.md) and Task 4's real ledger barriers: missing `stopOwned` fails before spawn, both send/interrupt barrier orders, native resolution and channel close during a response barrier, missing `availableDecisions`, unsupported requests, the 30 s interrupt bound with fake timers, a thrown owned stop, and `routeAnswerBarrier` refusals (stale generation, unknown, mismatched or repeated response). The concern pass adds: lost-create recovery through the loaded-thread lookup (pagination, baseline exclusion, gate before the rejoin), ambiguous/foreign/old/unreadable candidates, a failed rejoin, a refused `thread/start`, `turn/start` and steer error mapping, a send during pending MCP admission, a send written while the interrupt waits for a turn id, an actual `completed` terminal racing an interrupt, and the MCP `always` label from the context's user layer. |
| `isolation.test.js` | `assertNetworkIsolation` with an injected interface listing and connect. |
| `question-mcp.test.js` | Real loopback HTTP: auth, Origin, path and size refusals, `tools/list`, argument validation (`-32602`, nothing recorded), stable ids, record ordering (barrier before the first result byte), web/local/secret rules, repeated `responseId`, concurrent answers, `invalid_response`, client abort, hold ceiling and shutdown, failed write after the barrier, recovery mapping, and no answer value or hash in any record, log or error. The hold ceiling uses a short injected `holdMs` instead of fake timers, because fake timers interfere with the real socket I/O. Task 7 makes the held-answer heartbeat check count the server's own keepalive writes (after at least one was written while held), not bytes the client received, which could include a keepalive written before cleanup and delivered late. Task 6 adds four `onSettled` throw regressions: withdrawal and receipt record failures keep their original error and log, a native abort never leaves an unhandled rejection, and a dispatched answer stays dispatched. |
| `codex-config-gate.test.js` | Table-driven over pinned `ConfigLayer` shapes: one row per refusal reason, reason order, inert disabled project layers, legacy managed layers, session-flag drift, user-layer trust, the server allowlist and an enabled layer without `disabledReason`. |
| `db-bridge.test.js` | Task 7, in the default suite (no namespace): bytes both ways from the inside TCP listener through `db.sock` to a local echo target, every `db.sock` connection reaching only the configured target, `database_bridge_refused` for a host other than `127.0.0.1` or a portless URL, and `db.sock` 0600 in a 0700 directory, both removed on close. |
| `netns-launcher.test.js` | `runOuter`/`runInner` with injected execution (never spawns `unshare` or a native): root fallback only when an attempt ends before readiness, no rerun after the command started, exit 86 passed through, `network_isolation_unavailable` after both mappings fail or a tool is missing, readiness only after setup and isolation, cleanup after setup whether it succeeded or failed (a failed cleanup runs nothing), the setup plan that saves and restores an existing `/sys/fs/cgroup` mount around the sysfs remount and never invents one, and mountinfo checks that detect a shadowed cgroup mount or shared propagation. Task 7: no bridge without the connector test URL; the outside bridge starts before unsharing, the URLs pass unchanged with only the socket path added, and it closes with the suite; a refused URL exits `database_bridge_refused` before any namespace; inside, the forwarder starts after setup and stays up through the isolation check and the command. |
