# Collaboration collab

[Parent documentation](<../../../README.md>)

- [attention-view.tsx](<attention-view.tsx>) — Scoped paginated attention, duplicate/cursor guards, bounded Load more and current read cursors. Filters by the Current project selection and clears items when it changes; a Mark read that finishes after a switch does not reload the old scope. If the project catalog never loaded it shows an error with Try again.
- [board-view.tsx](<board-view.tsx>) — Authorized project board, persisted ordering and bounded live refresh. Scope is the `projectId` link, otherwise the Current project selection; it waits for the selection to validate, and a scope change closes an open create dialog. A read-only selected project shows a refusal note instead of New task. Move and create responses from an earlier scope visit are ignored, using a per-transition generation so returning to the same filters (A to B to A) does not revive them (no insert, rollback or error on the new board), and a pending old-scope move does not block the new scope's refresh. A workspace-only link sets the header to All projects, again on each Back/Forward visit.
- [create-task-dialog.tsx](<create-task-dialog.tsx>) — Backlog capture without repository or execution prerequisites. Offers only the selected project (or every writable project for All projects) and refuses to submit into a project outside that list.
- [projects-view.tsx](<projects-view.tsx>) — Projects list grouped by client and project detail with overview, run and test instructions. Members read; `project.admin` edits with optimistic versioning and a reload path on conflict. Settings links appear only for project or membership admins. A saved rename refreshes the shared catalog (header and list). When the revalidated catalog drops the project, or the catalog request is refused (401/403), the open overview and draft are replaced by "not found" and late load/save responses are ignored. A transient catalog failure keeps the draft.
- [execution-badge.tsx](<execution-badge.tsx>) — Client-safe execution and host reachability projection.
- [settings-view.tsx](<settings-view.tsx>) — Execution defaults keep an edited draft and its base version through catalog revalidation; a competing write makes Save return a conflict with Reload defaults. Capability-scoped client/project membership and invitations, workspace-defined roles, catalog-backed execution choices and usage coverage. Membership-only administration does not fetch execution mappings or hosts. Work and summary profiles/models remain separate, including disabled summaries and known offline configurations.
- [task-detail.tsx](<task-detail.tsx>) — One vertical task flow in the board-preserving [task-drawer.tsx](<task-drawer.tsx>): context, progress, sessions, expandable evidence and separate human discussion. Closing is navigation, not termination.
- [task-sessions.tsx](<task-sessions.tsx>) and [new-session-dialog.tsx](<new-session-dialog.tsx>) — Explicit attended entry points. An existing linked project supplies its repository; New session can create a minimal Backlog task plus chat atomically.
- [start-task-work.tsx](<start-task-work.tsx>) — Ready-task Start queues unattended work without opening chat.
- [task-claim-execution-tab.tsx](<task-claim-execution-tab.tsx>) — Claim-backed ACP history, bounded live output, capability-gated steering, distinct Stop response/End session, permissions and structured replies.
- [chat-handoff-controls.tsx](<chat-handoff-controls.tsx>) — Prepare, review and confirm Build this. Confirmation alone starts work; the reviewed digest is copied into task content and a fresh unattended claim. Repository-less sessions cannot hand off. Request retries retain their intent, and chat stays open after confirmation.
- [chat-execution-settings.tsx](<chat-execution-settings.tsx>) — Agent/profile/model defaults backed by the public advertised catalog; stale writes preserve the draft.
- [retained-work-notice.tsx](<retained-work-notice.tsx>) — Internal-only cleanup outcomes in task progress. Missing reports are unknown; retained files need an operator to save or explicitly discard. Reports are historical observations, not current filesystem inspection.
- [task-ideas-tab.tsx](<task-ideas-tab.tsx>) — Source-linked ideas and explicit task conversion.
- [task-workpad-tab.tsx](<task-workpad-tab.tsx>) — Plans, open questions, check history, safe artifacts, delivery review and immutable human decision history. Decision history shows the saved review commit/worktree state, note and acknowledgment count; missing captures stay unknown. Optional decision notes are separate from delivery notes and clear after success or lost access.
